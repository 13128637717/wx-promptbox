## 背景与目标

微信开发者工具编译时报两处错误：`pages/prompt/edit.wxml` 的 placeholder 含字面量 `{{名称}}`，以及运行时 `module 'data/categories.json.js' is not defined`。目标是让编辑页能通过 WXML 编译，并让分类与提示词 JSON 在模拟器里被正确打进代码包。

## 方案概述

1. 占位文案改到页面 data，WXML 只绑定 `{{namePlaceholder}}`，避免编译器把花括号当成模板表达式。
2. 关闭开发阶段和上传时的「过滤无依赖文件」。该过滤会把 `require('*.json')` 生成的 `*.json.js` 模块当成无依赖文件丢掉，模拟器再 require 时就会报未定义。`__route__ is not defined` 是 WXML 编译失败后的连带错误，不单独处理。

## 具体改动

### 改动摘要

编辑页变量名占位符改为数据绑定，并在项目配置里关闭无依赖文件过滤，使 `utils/catalog.js` 引入的 JSON 能进入编译产物。

### 文件级变更

- **修改** `pages/prompt/edit.wxml` — 变量名输入框的 placeholder 改为 `{{namePlaceholder}}`
- **修改** `pages/prompt/edit.js` — data 增加 `namePlaceholder: '变量名，与正文中的 {{名称}} 一致'`
- **修改** `project.config.json` — `ignoreUploadUnusedFiles`、`ignoreDevUnusedFiles` 设为 `false`
- **修改** `project.private.config.json` — `ignoreDevUnusedFiles` 设为 `false`（私有配置会覆盖公共配置）

## 验证方式

`node tests/catalog.test.js`、`prompt.test.js`、`search.test.js`、`export.test.js` 均通过。微信开发者工具侧需重新编译后确认控制台不再出现上述两条报错；本次未能调用开发者工具完成模拟器编译。

## 备注

控制台里 HarmonyOS 与 `wx.getSystemInfoSync` 是基础库提示和废弃警告，不是本次编译失败原因。
